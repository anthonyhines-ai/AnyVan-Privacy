- In **both** bookings the number is the **delivery contact**, and **both deliver to the

## 5. Methodology / Learning (reusable)

How to run these two lookup types against the AnyVan Snowflake warehouse. Reuse the
templates below; swap the highlighted literals.

### 5.1 Where the data lives

| Data | Table | Key columns |
|---|---|---|
| Booking (listing) core | `CONFORMED.PRODUCTION.MASTER_LISTING` | `LISTING_ID`, `LISTING_STATUS`, `LISTING_STATUS_GROUP`, `LISTING_TERRORITY`*, `PICK_UP_DATE`, `LISTING_DELIVERY_DATE`, `LISTING_USER_ID`, `LISTING_CREATED_DATE`, `LISTING_FROZEN_STATUS` |
| Booking postcodes / addresses | `CONFORMED.PRODUCTION.DIM_ADDRESS` | `LISTING_ID`, `LISTING_PICK_UP_POSTAL_CODE`, `LISTING_DELIVERY_POSTAL_CODE`, `LISTING_PICK_UP_ADDRESS`, `LISTING_DELIVERY_ADDRESS` (geographic only — **no phone/contact data**) |
| Customer (account holder) | `CONFORMED.PRODUCTION.DIM_USER_CUSTOMER` | `USER_ID`, `FULL_NAME`, `EMAIL_ADDRESS`, `PRIMARY_PHONE_NUMBER`, `SECONDARY_PHONE_NUMBER` |
| Raw listing (address FKs) | `HARMONISED.PRODUCTION.LISTING` | `LISTING_ID`, `USER_ID`, `PICKUP_ADDRESS`, `DELIVERY_ADDRESS` |
| Per-address contact (name + phone) | `HARMONISED.PRODUCTION.ADDRESS` | `ADDRESS_ID`, `PHONE_NUMBER`, `MOBILE_PHONE_NUMBER`, `FIRSTNAME`, `LASTNAME`, `POSTCODE`, `TOWN`, `REGION` |

\* `LISTING_TERRORITY` is a **known intentional typo** in the schema — use it as-is.

### 5.2 Join map

```
MASTER_LISTING.LISTING_ID        = DIM_ADDRESS.LISTING_ID          -- postcodes/addresses
MASTER_LISTING.LISTING_USER_ID   = DIM_USER_CUSTOMER.USER_ID       -- account holder
HARMONISED.LISTING.LISTING_ID    = MASTER_LISTING.LISTING_ID       -- link raw <-> conformed
HARMONISED.LISTING.USER_ID       = DIM_USER_CUSTOMER.USER_ID       -- account holder (raw)
HARMONISED.LISTING.PICKUP_ADDRESS   = HARMONISED.ADDRESS.ADDRESS_ID -- collection contact
HARMONISED.LISTING.DELIVERY_ADDRESS = HARMONISED.ADDRESS.ADDRESS_ID -- delivery contact
```

- **Booking customer number** → `DIM_USER_CUSTOMER` (`PRIMARY`/`SECONDARY_PHONE_NUMBER`).
- **Collection / delivery contact number** → `HARMONISED.PRODUCTION.ADDRESS`
  (`PHONE_NUMBER` / `MOBILE_PHONE_NUMBER`), reached via `LISTING.PICKUP_ADDRESS` /
  `LISTING.DELIVERY_ADDRESS`. `DIM_ADDRESS` does **not** hold contact numbers.

### 5.3 Normalisation rules

- **Postcode:** `REPLACE(UPPER(pc), ' ', '')` — matches with or without the internal space.
- **Phone:** `RIGHT(REGEXP_REPLACE(num, '[^0-9]', ''), 10)` — strip all non-digits and
  compare the **last 10 digits**. This matches every stored format (`07497 700277`,
  `+447497700277`, `447497700277`, `7497700277`). For `07497 700277` the key is `7497700277`.

### 5.4 Template A — lookup by phone number (customer / collection / delivery)

```sql
-- Replace 7497700277 with the target number's last 10 digits.
WITH addr_match AS (
  SELECT ADDRESS_ID,
         TRIM(COALESCE(FIRSTNAME,'')||' '||COALESCE(LASTNAME,'')) AS contact_name,
         CASE WHEN RIGHT(REGEXP_REPLACE(COALESCE(PHONE_NUMBER,''),'[^0-9]',''),10)='7497700277'
              THEN PHONE_NUMBER ELSE MOBILE_PHONE_NUMBER END AS matched_number
  FROM HARMONISED.PRODUCTION.ADDRESS
  WHERE RIGHT(REGEXP_REPLACE(COALESCE(PHONE_NUMBER,''),'[^0-9]',''),10)='7497700277'
     OR RIGHT(REGEXP_REPLACE(COALESCE(MOBILE_PHONE_NUMBER,''),'[^0-9]',''),10)='7497700277'
),
cust_match AS (
  SELECT USER_ID, FULL_NAME,
         CASE WHEN RIGHT(REGEXP_REPLACE(COALESCE(PRIMARY_PHONE_NUMBER,''),'[^0-9]',''),10)='7497700277'
              THEN PRIMARY_PHONE_NUMBER ELSE SECONDARY_PHONE_NUMBER END AS matched_number
  FROM CONFORMED.PRODUCTION.DIM_USER_CUSTOMER
  WHERE RIGHT(REGEXP_REPLACE(COALESCE(PRIMARY_PHONE_NUMBER,''),'[^0-9]',''),10)='7497700277'
     OR RIGHT(REGEXP_REPLACE(COALESCE(SECONDARY_PHONE_NUMBER,''),'[^0-9]',''),10)='7497700277'
),
matches AS (
  SELECT li.LISTING_ID, 'Customer' AS role, cm.FULL_NAME AS matched_name, cm.matched_number
  FROM cust_match cm JOIN HARMONISED.PRODUCTION.LISTING li ON li.USER_ID = cm.USER_ID
  UNION ALL
  SELECT li.LISTING_ID, 'Collection contact', am.contact_name, am.matched_number
  FROM addr_match am JOIN HARMONISED.PRODUCTION.LISTING li ON li.PICKUP_ADDRESS = am.ADDRESS_ID
  UNION ALL
  SELECT li.LISTING_ID, 'Delivery contact', am.contact_name, am.matched_number
  FROM addr_match am JOIN HARMONISED.PRODUCTION.LISTING li ON li.DELIVERY_ADDRESS = am.ADDRESS_ID
)
SELECT
  m.LISTING_ID,
  LISTAGG(DISTINCT m.role, ', ') WITHIN GROUP (ORDER BY m.role) AS matched_roles,
  MAX(m.matched_name)   AS matched_name,
  MAX(m.matched_number) AS matched_number,
  ANY_VALUE(ml.LISTING_STATUS)                      AS listing_status,
  ANY_VALUE(ml.LISTING_TERRORITY)                   AS territory,
  ANY_VALUE(CAST(ml.PICK_UP_DATE AS DATE))          AS pick_up_date,
  ANY_VALUE(CAST(ml.LISTING_DELIVERY_DATE AS DATE)) AS delivery_date,
  ANY_VALUE(a.LISTING_PICK_UP_POSTAL_CODE)          AS pickup_postcode,
  ANY_VALUE(a.LISTING_DELIVERY_POSTAL_CODE)         AS delivery_postcode,
  ANY_VALUE(a.LISTING_PICK_UP_ADDRESS)              AS pickup_address,
  ANY_VALUE(a.LISTING_DELIVERY_ADDRESS)             AS delivery_address,
  ANY_VALUE(ml.LISTING_USER_ID)                     AS user_id,
  ANY_VALUE(CAST(ml.LISTING_CREATED_DATE AS DATE))  AS created_date
FROM matches m
LEFT JOIN CONFORMED.PRODUCTION.MASTER_LISTING ml ON ml.LISTING_ID = m.LISTING_ID
LEFT JOIN CONFORMED.PRODUCTION.DIM_ADDRESS a     ON a.LISTING_ID  = m.LISTING_ID
GROUP BY m.LISTING_ID
ORDER BY created_date DESC NULLS LAST;
```

### 5.5 Template B — lookup by postcode + date

```sql
-- Replace 'YO318LH' (postcode, spaces removed, upper-case) and the date '2026-07-09'.
SELECT
  l.LISTING_ID, l.LISTING_STATUS, l.LISTING_STATUS_GROUP, l.LISTING_CATEGORY_NAME,
  l.LISTING_TYPE, l.LISTING_TERRORITY, l.LISTING_FROZEN_STATUS,
  CAST(l.PICK_UP_DATE AS DATE)          AS PICK_UP_DATE,
  CAST(l.LISTING_DELIVERY_DATE AS DATE) AS LISTING_DELIVERY_DATE,
  a.LISTING_PICK_UP_POSTAL_CODE,  a.LISTING_PICK_UP_ADDRESS,
  a.LISTING_DELIVERY_POSTAL_CODE, a.LISTING_DELIVERY_ADDRESS,
  l.LISTING_USER_ID, l.LISTING_CHOSEN_PROVIDER_NICKNAME,
  CAST(l.LISTING_CREATED_DATE AS DATE)  AS LISTING_CREATED_DATE
FROM CONFORMED.PRODUCTION.MASTER_LISTING l
JOIN CONFORMED.PRODUCTION.DIM_ADDRESS a ON a.LISTING_ID = l.LISTING_ID
WHERE a.LISTING_ID IS NOT NULL
  AND ( REPLACE(UPPER(a.LISTING_PICK_UP_POSTAL_CODE),  ' ', '') = 'YO318LH'
     OR REPLACE(UPPER(a.LISTING_DELIVERY_POSTAL_CODE), ' ', '') = 'YO318LH' )
  AND ( CAST(l.PICK_UP_DATE AS DATE)          = '2026-07-09'
     OR CAST(l.LISTING_DELIVERY_DATE AS DATE) = '2026-07-09' )
ORDER BY l.LISTING_CREATED_DATE DESC;
```

### 5.6 Caveats

- `MASTER_LISTING` covers listings from **2022-01-01** onwards. Older/pre-2022 bookings may
  exist in `HARMONISED.PRODUCTION.LISTING` but will return NULL context via `MASTER_LISTING`.
- `LISTING_DELIVERY_DATE` is only populated for jobs with a distinct delivery leg (storage,
  multi-leg). For a standard single-day move, delivery happens on `PICK_UP_DATE`.
- Contact matching follows the **current** linked address (`LISTING.PICKUP_ADDRESS` /
  `DELIVERY_ADDRESS`). If an address was edited after booking, an older phone value that is
  no longer the linked address will not match.
- The last-10-digit rule could in theory match a foreign number sharing those trailing
  digits; for UK mobiles this is effectively unique. Confirm the full stored format
  (shown in `matched_number`) when precision matters.
- Searches above are **not** territory-restricted — they cover UK and international unless a
  `LISTING_TERRORITY` filter is added.
